# 峡谷组局室

路由 `/arena`，博客菜单“峡谷组队”。这是公开选手池：访客无需登录即可查看已经授权保存的游戏档案、比较五分路评分、选择十人分队。扫码前必须同意公开昵称、头像、英雄、战绩、赛季和评分。游戏登录凭据仅留在当前服务进程内存，不进入文件或公开接口。

## 部署与保存

沿用项目现有的 `npm run build`、standalone 镜像和 Nginx 反向代理，未要求修改 Dockerfile、Compose 或 Nginx。QQ、微信都通过官方 HTTPS 扫码流程工作，无 Chrome、Playwright 或新增系统软件依赖。

数据默认保存在 `${ATTACHMENTS_DIR}/.arena/players/`；当前 Compose 已设置 `ATTACHMENTS_DIR=/app/attachments` 并挂载宿主机目录，所以推新镜像后档案仍保留。附件中心保留 `.arena` 作为内部目录，不能通过附件分组接口进入。开发环境未设置该变量时使用项目 `data/arena/`。可选 `ARENA_DATA_DIR` 可改变保存位置，不是必填配置。每个选手一个 JSON 文件，保留最新档案和最近 30 次同步快照，原子替换，写入前只投影允许的游戏字段。

本机档案不会自动上传到服务器，也不会打包进生产镜像：`data/` 被 Git 忽略，并从 Next standalone 文件追踪中排除。服务器首次授权后自动建立自己的档案。运行账号需要能写现有附件挂载目录；这与附件中心现有权限要求一致。

可选 `ARENA_PROXY` 用于服务端网络代理；默认直接联网。反向代理保留原始 Host 时不用额外域名配置。特殊代理架构可设置 `ARENA_PUBLIC_ORIGIN=https://你的域名` 固定来源校验。没有任何必填的新环境变量。

退出只释放临时授权，公开档案继续保留。本人重新扫码后可更新数据、保存分路偏好、移除自己的公开档案。服务重启后需要重新扫码才能修改本人资料，公开只读档案仍可访问。暂时只支持单个 Next 服务实例共享本地文件，未实现多节点文件锁或分布式登录状态。

## 数据范围

当前 QQ 账号真实联调读取 133 个英雄条目、S22–S45 的 24 个赛季快照、最近 30 场对局。132 个英雄带场次/胜率/战力，1 个相关字段缺失；零场英雄保留。熟练度为接口等级。最高战力、历史最高段位和逐日段位曲线不作猜测。上游未明确累计英雄统计的模式范围，因此不当作全排位样本。

微信扫码、营地登录、数据同步及文件保存已通过真实账号端到端验证：返回 133 个英雄条目（其中 54 个带场次数据）、17 个赛季记录，最近对局接口返回 0 场。QQ 纯 HTTP 流程已通过本人真实扫码响应验证：官方中转页解析、取得最终回调地址、校验 state、营地会话交换以及数据读取和文件保存均已走通，返回 133 个英雄条目、24 个赛季和 30 场最近对局。接口未返回的字段保持为空，不补造数据。

## QQ 确认后授权失败的修复

第一版本地工具通过浏览器执行完整 QQ 登录页面；迁移到无需浏览器的 HTTP 实现时，遗漏了官方移动中转页的最终地址解析步骤。2026-10-16 本人真实扫码返回的入口是 `https://imgcache.qq.com/open/connect/widget/mobile/login/proxy.htm`，参数位于 fragment，并可能包含第二个 `#`。该[官方中转页](https://imgcache.qq.com/open/connect/widget/mobile/login/proxy.htm)会用 `redirect_uri_key` 请求 `https://openmobile.qq.com/oauth2.0/m_get_redirect_url?keystr=…`，通过 `_Callback(JSON)` 得到最终 `auth://tauth.qq.com/` 回调。此前的实现只处理直接回调和普通重定向，因而在手机确认后失败。

现在严格识别该中转页地址及营地 AppID，只请求固定 QQ 官方接口，不把包含授权信息的 fragment 发往中转页面；仅解析 JSONP 数据，不执行远端脚本。最终回调必须包含与本次扫码一致的 state。QQ 轮询、回调、营地会话交换失败分别显示不同提示。回归测试覆盖真实响应结构的虚构样例、错误 AppID、重复字段、不相关域名、过期结果、state 缺失/不匹配以及脚本注入。真实授权和原始响应仅在诊断进程内存中使用，没有保存为测试样例。

## 评分

版本 `arena-explainable-v1`，0–100 是本应用内部的相对指数，不是官方 MMR、段位百分位或获胜概率。

1. 当前段位和星数提供基线，近三季可用段位按新旧加权，历史最高段位不直接当当前水平。
2. 英雄累计胜率使用 Beta(12,12) 收缩；单英雄最多 120 个有效样本，展示胜率推导的样本再降低权重。兼任多个分路的英雄按目录分路分摊，不把它称为真实分路场次。
3. 明确排位、时间有效且处于同步时间前 30 天的最近最多 20 场仅提供小幅近况修正。开房、人机、匹配、巅峰和未知模式不混入近期排位。
4. 战力和 KDA 不直接换算实力；缺数据维持中性先验和较低模型置信度。
5. 本人可标注偏好/避免分路，以及每路 -15 至 +15 的明确手动校正。五路均展示分数、模型置信度、样本说明和计算依据。

目录版本 `catalog-roles-2026-10-16-v1` 采用保存的官方目录 roles 映射：1 对抗、2 打野、3 中路、4 发育、5 游走。hero_type 职业分类不直接当分路。

## 公平分队

版本 `arena-bounded-exhaustive-v1`。选十位不同选手，每队五路各一人，锁位/锁队是硬约束，无解时明确拒绝。枚举合法分队和位置排列，目标同时考虑团队平均分差、五路平均差、最大对位差、偏好适配及两队置信度差。十人的规模有固定上限，不使用无限搜索。

先找到最低目标值，再从满足额外公平阈值的近优候选中按 seed 抽取。改变 seed 可变化，固定 seed 可复现；“重组变化”为零时选择最优确定解。随机性不会解除锁位、重复选手或超出候选公平阈值。结果显示对位差、模型均值差和算法理由；不承诺真实对局一定接近。

这版不依赖大语言模型或付费 API。未来可在用户明确授权后把匿名统计发给模型生成解读，硬约束和分队校验仍应由本地算法执行。
